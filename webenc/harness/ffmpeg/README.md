# FFmpeg preprocessing qualification

Run against a Vite development server with `WEBENC_URL` and a managed tmpfs
fixture directory in `WEBENC_TEST_OUTPUT`:

```sh
WEBENC_URL=http://127.0.0.1:4175 \
WEBENC_TEST_OUTPUT=/dev/shm/segacd-fmv-cavc/artifacts/FIXTURE/data \
WEBENC_TEST_LONG=1 node webenc/harness/ffmpeg/verify.mjs
```

The fixture directory supplies `source-60fps.mp4` and `source-59.94fps.mp4`, as
generated by `scripts/verify-source-import.mjs`. The long option creates a
one-minute 640x360/24fps H.264 source with 48 kHz AAC audio under the same lease.
No video-specific native output is supplied to the browser.

The worker runs the production normalizer on the same original source bytes.
The native reference independently executes the manifest's FFmpeg commands;
its geometry filter is checked against `tools/video_geometry.py`. Compare every
decoded RGB pixel, every signed-16 PCM sample, frame count and audio length.
The source crop, SAR, output fps and Lanczos filter are frozen per case.

The reference uses `-cpuflags 0`, disabling native CPU-specific optimized
routines. Default native FFmpeg's SIMD color conversion and audio routines can
round differently from the Wasm core. This condition is recorded explicitly;
passing these tests is not a claim of parity with arbitrary FFmpeg versions,
input codecs or the native encoder's default CPU options.

Core 0.12.10 / FFmpeg 5.1.4 and native FFmpeg 8.0.1 pass the qualified nine
cases: 60-to-30, 59.94-to-30, trimmed interval, square-pixel pad, center crop,
custom crop/aspect, silent source, 48 kHz stereo AAC and the full 1,440-frame
minute. `WEBENC_CASES` selects a comma-separated case list. Set
`WEBENC_TEST_CANCEL=1` to exercise cancellation during actual FFmpeg extraction
using the minute fixture. Persistent TSV hashes and
JSON receipts live in `logs/webenc_ffmpeg_scalar_preprocessing_*`; disposable
PNGs, PCM, manifests and test media stay under the managed fixture directory.
This harness qualifies preprocessing. Actual CAVC stream, MP4, ISO and CUE
generation are separately exercised by `scripts/verify-encode.mjs`.
